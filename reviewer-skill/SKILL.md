# Access review

When asked to help complete an access review, use the connected Access Reviews tools. Start with list_my_reviews and get_review_items for the relevant assigned campaign. Resume its current state. Follow pagination. If multiple campaigns are assigned, ask which to open.

For Active Directory, use the separate Dana Personal Context connector’s `search_personal_context` tool before proposing actions. Search for the person and the responsibility in question. For Alex Rivera, search for invoice follow-up. If the connector is unavailable, open `sales-handoff.md` from the personal agent’s project sources or workspace. Confirm that you found the Sales Ops handoff. Read the simulated Knowledge Hub entry, activity, and policy from Lumos. Explain which guidance supported the original Accounts Receivable suggestion and how the handoff changes Alex’s proposed action under the policy. If the handoff is unavailable, ask for it and leave Accounts Receivable pending. Keep the excerpt and its private source ID out of Lumos calls. Use an audit-safe reason such as “No current business need under the invoice follow-up policy.”

Summarize the full queue by count and recommendation after reading every page. Show context-driven changes and unresolved permissions first, followed by routine groups with a shared reason. If the reviewer asks to start with one person, propose decisions only for that person and state that the other permissions are still pending. Use names and permissions in the conversation and keep internal IDs in tool payloads. Skip recorded rows.

Group permissions with the same well-supported rationale. Keep identities and exact permissions distinct. Check source excerpts and versions with get_evidence. For uncertain items, inspect relevant context the reviewer has supplied or authorized in the host, such as an attached conversation or project notes. Use a ticket ID, owner, or date from that context to target search_review_evidence. Keep private context on the host. Search with the smallest useful clue, such as an approval ID, and avoid copying private messages into tool calls.

Check person, exact entitlement, effective date, expiry and conditions before relying on an exception. Compare Albus's suggestion with your own evidence-based judgment. Explicitly identify what the personal context added and explain why it changes or reinforces your recommendation. A personal conversation can establish business context, such as a staffing handoff. Check formal authorization separately against product evidence.

Ask the reviewer a focused question only when their answer could change an unresolved decision. For example, ask whether they have a current renewal reference for a particular permission or want to leave that item pending. Use the host's native question choices when available and allow a typed answer. Otherwise ask in chat and wait. Treat personal notes or answers as leads to verify. Leave a grant pending when needed evidence or judgment is missing.

Call prepare_review_batch for the exact decisions you propose. Copy the run_id exactly from the latest get_review_items result. Use retain to approve and revoke to reject. If staging reports a restart, fetch the items again and retry with the newly returned run_id. Ask for confirmation only after you receive a proposal ID. Show the prepared rows with person, permission, action, and evidence-backed reason, and summarize the remaining queue. Keep the private conversation out of the draft. Add context_summary only if the reviewer expressly approved the specific audit-safe wording for sharing with the product. Use the host’s native confirmation controls when available. If the reviewer changes anything, prepare a replacement proposal and show it before asking again.

Only after confirmation call record_review_batch with the approved proposal ID. Report recorded, pending and blocked items separately. Use get_review_status to read the saved receipts. On a stale item, fetch its new evidence, prepare a new proposal, and ask again. On an uncertain delivery, retry the same confirmed proposal ID. If a reviewer handles an item in the product, refresh the review and honor that decision. Explain that this synthetic workspace records decisions and receipts without changing real access.

After a confirmed Accounts Receivable reversal is recorded, suggest a separate IT request to verify the Sales Ops handoff and update the Active Directory review context in the Lumos Knowledge Hub for future suggestions. Show a short, unsent draft about the role-level change without naming Alex or quoting the private note. Do not send the request or update the Knowledge Hub as part of the review.
